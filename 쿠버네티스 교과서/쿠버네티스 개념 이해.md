쿠버네티스: 컨테이너를 실행하는 플랫폼
쿠버네티스의 두 가지 핵심 개념
1. 애플리케이션 정의에 사용되는 API
2. 애플리케이션이 실제로 동작하는 클러스터
- 클러스터: 컨테이너 런타임이 동작하는 여러 대의 서버가 모여 쿠버같은 하나의 논리적 단위를 구성한 것
- 클러스터 관리자: 노드라고 하는 각각의 서버를 관리
- 클러스터의 목적: 애플리케이션을 실행하는 것 

### 파드와 디플로이먼트
- 쿠버네티스가 하나 또는 그 이상의 컨테이너를 관리하는 데 사용하는 단위, 자신만의 가상 IP주소를 가진다. 쿠버네티스에서 컴퓨팅의 최소 단위
- 원시 타입 리소스이므로 일반적으로 파드를 직접 실행하지 않는다 -> 파드를 관리할 컨트롤러 객체를 따로 만들게 된다.
- 파드에 포함된 IP 주소가 여러 개이면 이들은 localhost로 서로 통신할 수 있다.
- **쿠버네티스가 직접 컨테이너를 실행하지 않음** -> 컨테이너를 생성할 책임을 해당 노드에 설치된 컨테이너 런타임에 맡기는 형태 => 파드가 컨테이너를 추상화 시킨 이유다. 
- 파드는 쿠버네티스가 관리하는 리소스, 컨테이너는 쿠버네티스 외부에서 관리된다.

자기수복성
1. 컨테이너를 파드로 추상화 -> 이상을 일으킨 컨테이너는 일시적일 뿐, 파드는 그대로 있으므로, 새로운 컨테이너를 추가하여 파드 상태를 복원하면 된다. 

컨트롤러 객체: 다른 리소스를 관리하는 쿠버네티스 리소스
디플로이먼트: 여러개의 컨트롤러 객체 중에서 파드를 주로 관리하는 컨트롤러 객체, 파드 위로 얹히는 또 다른 추상화 중 하나 
ex) 어떤 노드가 고장을 일으켜 파드가 유실 -> 디플로이먼트가 대체 파드를 다른 노드에 실행함.
